## Lessons

1. **The morning decision file must be treated as non-negotiable, not aspirational.** Of ten
   trading days in July so far (2026-07-01 through 2026-07-28), a morning decision file was
   written on exactly two: 2026-07-13 and 2026-07-23. The other eight days have no written
   record of what was reviewed or decided. The journal can note what happened; it cannot
   reconstruct what was considered. A daily process that records decisions only intermittently
   is not a daily process — it is an occasional one. The standard is one decision file per
   trading day, every trading day, written before any order is placed.

2. **Our 1.30 pp "lead" over SPY is shrinking as SPY recovers, and it never represented real
   outperformance.** On 2026-07-23 the lead was 1.67 pp. Today it is 1.30 pp. Forty-two
   calendar days after opening, the portfolio holds $1,000,000 in cash and has experienced
   zero market exposure. The portfolio's mandate — own a few wonderful businesses bought at
   sensible prices, beat SPY over years — requires actually owning things. Permanent cash is
   not a strategy; it is an indefinite deferral of the strategy. If valuations remain elevated
   and no name passes the margin-of-safety test, that is a valid reason to wait. But the
   reasoning must be written down each day and should acknowledge the cost of waiting
   (opportunity cost, benchmark drift risk if SPY rallies hard).

3. **The FOMC meeting on July 28-29 was the relevant macro event today; no decision file
   captured this.** The July 23 decision file correctly identified the Fed meeting as a near-
   term catalyst for volatility. Had a July 28 decision file been written, it would likely
   have cited FOMC-day caution as additional reason to hold cash. Instead, the reasoning
   exists only in this journal's after-the-fact inference, which is not the same as a
   documented decision made before the market opened. Tomorrow (July 29) is the second day
   of the FOMC meeting and the day a rate decision is expected. A morning decision file must
   be written before any order is placed or the session is closed.
